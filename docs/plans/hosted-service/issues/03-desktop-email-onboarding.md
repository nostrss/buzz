# 03: 데스크톱 이메일 로그인 온보딩 (플래그 분기)

**What to build:** 계정 서비스 주소가 빌드에 들어 있으면 앱의 첫 화면이 "이메일로 시작"이다. 이메일과 코드를 넣으면 키 관련 화면 없이 릴레이에 접속되고, 커뮤니티가 없으면 "커뮤니티 만들기 / 초대 링크 붙여넣기" 화면이 나온다. 초대 링크로 앱을 열었다면 로그인이 끝나자마자 자동으로 조인된다. 주소가 없으면 upstream 온보딩이 그대로 나온다.

**Blocked by:** 02 (이메일 + 6자리 코드 로그인 API)

**Status:** ready-for-agent

- [ ] 빌드 환경변수 하나(계정 서비스 URL)로 분기한다. 분기 지점은 기기 온보딩 진입 한 곳이며, 우리 화면은 새 feature 디렉터리의 새 파일에 둔다.
- [ ] 이메일 입력 화면: 이메일 형식 검증, "코드 보내기", 분당 1회 안내 표시.
- [ ] 코드 입력 화면: 6자리 입력, 틀리면 남은 횟수 표시, 만료·폐기 시 "코드 다시 보내기".
- [ ] Tauri 커맨드가 계정 서비스의 start/verify/me/logout을 호출한다. 응답의 nsec은 기존 키체인 저장 경로로 커밋하고 기존 키가 있으면 덮어쓴다. 세션 토큰은 같은 키체인 블롭에 저장된다.
- [ ] 앱 재시작 시 키체인의 세션으로 `/v1/me`를 불러 로그인 화면을 건너뛴다. 401이면 이메일 화면으로 돌아간다.
- [ ] 로그인 후 커뮤니티 목록이 있으면 첫 커뮤니티에 접속하고, 없으면 "만들기 / 초대 링크" 두 카드 화면을 보여준다. "만들기" 카드는 이 티켓에서는 비활성이다.
- [ ] 초대 링크 붙여넣기는 upstream 조인 흐름을 그대로 탄다. 초대 링크로 앱을 연 경우 기존 대기 게이트가 로그인 뒤 자동 조인을 이어간다.
- [ ] 로그아웃하면 키체인의 세션과 신원 키가 삭제되고 이메일 화면으로 돌아간다.
- [ ] 플래그가 없으면 upstream 온보딩이 바이트 단위로 동일하게 동작한다(기존 smoke 스펙 통과).
- [ ] mock bridge에 계정 서비스 커맨드 스텁을 추가하고 Playwright smoke 스펙으로 이메일 → 코드 → 두 카드 화면, 코드 오류 표시, 초대 링크 자동 조인, 키 관련 문구 부재를 검증한다.
